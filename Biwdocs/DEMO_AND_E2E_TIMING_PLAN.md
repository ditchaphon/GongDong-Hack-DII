## 1. ทดลอง Flow ทั้งระบบใช้เวลากี่นาที?

การประเมินเวลาสำหรับทดลองใช้งานจริงบน LINE LIFF 2 เครื่อง (อ้างอิงลำดับขั้นตอนใน [BUYER_SELLER_ORDER_FLOW.md](file:///D:/Project/GongDong-Hack-DII/Biwdocs/BUYER_SELLER_ORDER_FLOW.md) และ [MANUAL_TEST_GUIDE.md](file:///D:/Project/GongDong-Hack-DII/Biwdocs/MANUAL_TEST_GUIDE.md)):

| ช่วงการทดสอบ | ขอบเขตและหน้าจอที่ใช้งาน | เวลาโดยประมาณ |
|---|---|---:|
| **1. Onboarding + เปิดร้าน + เติมเครดิต** | LINE Login 2 บัญชี → ตั้งชื่อเล่น/Avatar + PDPA (`/setup`) → ตั้งค่าร้าน/จุดนัดรับ/PromptPay/KYC (`/seller/setup`) → เติมเครดิต PromptPay QR + แนบสลิป SlipOK (`/seller/credits`) | **3–4 นาที** *(ทำครั้งเดียวตอนเตรียมบัญชี)* |
| **2. ลงขายหนังสือ (Single + Set)** | ลงขาย 4–5 ขั้น (`/seller/list` → `details` → `step-2` อัปโหลดรูป 4 มุม → `step-3` เช็กคุณภาพ 5 จุด → `step-4` ตั้งราคา): ทดลอง **เล่มเดียว (สแกน/กรอก ISBN)** + **ยกชุด (SET + ระบุเล่มที่ขาด)** | **3–4 นาที** *(~1.5–2 นาที/รายการ)* |
| **3. Flow นัดรับ (Meetup + รหัส 6 หลัก)** | ค้นหา & ดูเทียบ ISBN (`/book/[id]`) → สั่งซื้อ (`/cart`) → LINE OA Push แจ้งผู้ขาย → กดรับ (`-1 เครดิต`) → แชท (ทดสอบส่งเบอร์โทรให้ Mask `•••`) + นัดเวลา (`/orders/[id]/schedule`) → กรอกรหัสส่งมอบ 6 หลัก (`/api/orders/:id/handover`) → รีวิว (`/orders/[id]/review`) | **3–4 นาที** |
| **4. Flow ส่งพัสดุ (Parcel COD)** | เพิ่มที่อยู่ (`/addresses/edit`) → สั่งซื้อ COD (ตรวจค่าส่งรวมเพดาน `฿150` สำหรับชุด) → ผู้ขายรับ → กรอกขนส่ง/เลขพัสดุ/รูปกล่อง (`/orders/[id]/tracking`) → ผู้ซื้อถ่ายรูปยืนยันรับของ + รีวิว (`/orders/[id]/receive`) | **3–4 นาที** |
| **5. Edge Cases & Admin *(กรณีตรวจ QA เต็ม)*** | ยกเลิกออเดอร์, รายงาน No-Show (`/orders/[id]/no-show`), เปิดข้อพิพาท `DISPUTED` และจัดการบน [admin/page.tsx](file:///D:/Project/GongDong-Hack-DII/frontend/src/app/admin/page.tsx) (`/admin`) | **+5–8 นาที** |

### สรุปเวลาที่ใช้ทดสอบ
- **Pre-staged Happy Path (ข้ามขั้นเปิดร้าน/เติมเครดิต):** **~10–12 นาที**
- **E2E Happy Path ทั้ง 2 เส้นทาง (นัดรับ + พัสดุ ตั้งแต่ต้นจนจบ):** **~12–16 นาที**
- **Full QA (รวม Onboarding + Edge Cases + `/admin`):** **~20–25 นาที**

## 2. โครงสร้างการนำเสนอ 7 นาที (Pitch Deck 3.5 นาที + Live Demo 3.5 นาที)

```
0:00 ─────────────────────── 3:30 ─────────────────────── 7:00
│         Pitch Deck         │       Live Demo 2 เครื่อง      │
│  Problem → Solution → Biz  │  Meetup E2E + Highlight UX   │
```

### ช่วงที่ 1: Pitch Deck (0:00 – 3:30 | 3.5 นาที)
1. **Problem (~45 วิ):** ซื้อหนังสือมือสองในกลุ่ม Facebook/OpenChat เสี่ยงโดนโกงบัญชีม้า, สภาพไม่ตรงปก, นัดรับแล้วเบี้ยว, และดีลหลุดไปคุยส่วนตัวจนคุมความปลอดภัยไม่ได้
2. **Solution ("จบในกองดอง" ~60 วิ):** LINE LIFF Marketplace ที่คุมทุกจุดตั้งแต่เช็กสภาพ, จ่าย/นัดรับ, แชท, จนถึงปิดดีลด้วยรหัส 6 หลัก
3. **Trust & Tech Architecture (~60 วิ):**
   - **UX จุดขาย:** เช็กคุณภาพ 5 จุด + รูป 4 มุมซูมตำหนิ, ขายยกชุด (SET), **ISBN Smart Compare** เทียบราคา/เกรด/`% ตรงปก`
   - **Anti-Fraud:** Frictionless KYC ผูกบัญชีรับเงินกับสลิป (SlipOK), Contact Masking ปิดเบอร์/LINE ID ในแชท, Pre-accept privacy lock, และ **6-Digit Handover Code**
4. **Business Model (~45 วิ):** ลงขายฟรี หัก **1 เครดิต** เฉพาะตอนผู้ขายกดรับออเดอร์จริง (`฿20 = 3` / `฿50 = 10` / `฿100 = 25` — เฉลี่ย `฿4–7/ออเดอร์`)

### ช่วงที่ 2: สคริปต์ Live Demo สด 2 เครื่อง (3:30 – 7:00 | 3.5 นาที)

ใช้ **"นัดรับ (Meetup + รหัส 6 หลัก)" เป็นเส้นเรื่องหลัก** โดย Pre-stage ข้อมูลร้านและหนังสือไว้ก่อนขึ้นเวที แล้วแทรกหน้า **ยกชุด (SET)** และ **ISBN Smart Compare** ให้กรรมการเห็นครบทั้งจุดขาย UX และระบบกันโกง

> **การจัดหน้าจอแนะนำ:** ขึ้นจอโปรเจกเตอร์แบบวางคู่ 2 เครื่อง (หรือ Mirror มือถือ Buyer + Seller เคียงกันบนจอเดียว) เพื่อลดเวลาสลับหน้าต่าง

| เวลา | ฝั่งที่กด | หน้า / Route | ลำดับการคลิก & สิ่งที่พูดกับกรรมการ |
|---|---|---|---|
| **3:30 – 4:20**<br>*(50 วิ)* | **ผู้ซื้อ** | `/` → `/book/[id]` | 1. หน้าแรกกดฟิลเตอร์ **`การ์ตูนยกชุด`** แล้วแตะ **หนังสือยกชุด** 1 รายการ → ชี้ Badge ยกชุด + จำนวนเล่ม/เล่มที่ขาด (`missingVolumes`)<br>2. ย้อนกลับมากด **หนังสือเล่มเดียวที่มีหลายร้านขาย** → โชว์รูป 4 มุม + **ผลตรวจคุณภาพ 5 จุด** + กดซูมตำหนิ<br>3. เลื่อนลงส่วน **ISBN Smart Compare** → โชว์การเทียบราคา / เกรด / `% ตรงปก` ระหว่างร้านในหน้าเดียว |
| **4:20 – 4:50**<br>*(30 วิ)* | **ผู้ซื้อ → ผู้ขาย** | `/cart` → `/cart/success` | 1. กด **`ใส่ตะกร้า`** → เลือก **`นัดรับ ฿0`** → กด **`ส่งคำขอซื้อ`**<br>2. ชี้ให้ดูหน้าออเดอร์ฝั่งผู้ซื้อ: **แชทและพิกัดยังไม่เปิด** จนกว่าผู้ขายจะกดรับ (กันร้านปฏิเสธแล้วแอบตามไปขายนอกแอป)<br>3. ชี้ไปที่จอผู้ขาย: โชว์ **LINE OA Push Notification (Flex Card)** ที่เด้งแจ้งเตือนคำขอใหม่ |
| **4:50 – 5:45**<br>*(55 วิ)* | **ผู้ขาย ↔ ผู้ซื้อ** | `/orders/[id]` & `/orders/[id]/schedule` | 1. ผู้ขายแตะจาก LINE OA เข้าหน้าออเดอร์ → กด **`รับออเดอร์`** (ชี้ยอดเครดิตที่ลดลง `-1` และหนังสือถูกล็อกทันที)<br>2. **ทดสอบ Contact Masking สด:** พิมพ์ข้อความในแชทที่มีเบอร์โทร/LINE เช่น `โทร 0812345678` → ระบบ Mask เป็น `•••` ทันที (ฝั่งผู้ซื้อจะ polling อัปเดตใน ~8 วินาที)<br>3. ผู้ขายกดเสนอเวลานัดรับ (`/orders/[id]/schedule`) → ผู้ซื้อกดยืนยัน |
| **5:45 – 6:30**<br>*(45 วิ)* | **ผู้ซื้อ → ผู้ขาย** | `/orders/[id]` → `/orders/[id]/review` | 1. หลังยืนยันนัด หน้าจอผู้ซื้อจะแสดง **รหัสรับของ 6 หลัก** (ฝั่งผู้ขายจะไม่เห็นจนกว่าจะเจอตัวจริง)<br>2. ผู้ขายกรอกรหัส 6 หลักที่ผู้ซื้อบอก → ออเดอร์ปิดเป็น **`COMPLETED`** ทันที (กันเบี้ยวนัด/กันหลีกเลี่ยงระบบรีวิว)<br>3. ผู้ซื้อกดให้ดาว + ติ๊ก **`ตรงเกรด`** (`/orders/[id]/review`) เพื่อสะสมคะแนนร้าน |
| **6:30 – 7:00**<br>*(30 วิ)* | **ผู้ขาย / ปิดท้าย** | `/seller/list` *(Quick Peek)* | *(ถ้าเวลาเหลือ 20–30 วินาที)* กดเปิด `/seller/list` ให้เห็นสวิตช์ **เล่มเดียว / ยกชุด** และช่อง **สแกนบาร์โค้ด ISBN** จากนั้นสรุปปิดท้ายจบที่ `7:00` พอดี |

## 3. Pre-Stage Checklist ก่อนขึ้นเวที

### ข้อมูลบัญชี & สินค้าบน Production
- [ ] **บัญชีผู้ขาย (Seller):** สมัคร/ตั้งค่า PDPA แล้ว, เปิดร้านใน `/seller/setup` แล้ว, ยืนยันบัญชีรับเงินแล้ว, มีเครดิตคงเหลืออย่างน้อย **3–5 เครดิต**, มีจุดนัดรับตั้งค่าไว้เรียบร้อย
- [ ] **บัญชีผู้ซื้อ (Buyer):** ตั้งชื่อเล่น/Avatar + PDPA (`/setup`) แล้ว, **ตะกร้าสินค้าว่าง**, มีคำขอซื้อค้างน้อยกว่า 3 ออเดอร์ (จำกัดค้างไม่เกิน 3 คำขอ/คน)
- [ ] **หนังสือตัวอย่างสำหรับ Demo (อย่างน้อย 3 รายการ):**
  1. **หนังสือเล่มเดียว (ร้าน Demo Seller):** รูปครบ 4 มุม, มีอย่างน้อย 1 จุดตำหนิให้กดซูมดู, เปิดรับ `นัดรับ`
  2. **หนังสือเล่มเดียวอีกร้านที่ใช้ ISBN เดียวกัน** (แต่เกรด/ราคาต่างกัน) เพื่อให้ **ISBN Smart Compare** แสดงผลเทียบ 2 ร้านขึ้นไป
  3. **หนังสือยกชุด (SET):** ใส่ข้อมูลจำนวนเล่มและ `missingVolumes` เพื่อให้กดดูในฟิลเตอร์ `การ์ตูนยกชุด` บนหน้าแรกได้ทันที

### ความพร้อมระบบ Production
- [ ] ตรวจ Environment Variables บน Vercel Backend: `ADMIN_LINE_USER_IDS`, `CRON_SECRET`, `ADMIN_API_KEY`, `SLIPOK_API_KEY`, `SLIPOK_BRANCH_ID`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`
- [ ] ตรวจ LINE Developers Console: Messaging API Webhook URL ชี้ไปที่ `https://<backend-domain>/api/webhooks/line`, เปิด Use webhook และให้บัญชี Demo ทั้งคู่แอดเพื่อน LINE OA เรียบร้อยแล้วเพื่อให้ Push Notification เด้งได้จริง
- [ ] ซ้อม 1 รอบด้วยอุปกรณ์จริง + เน็ตที่จะใช้บนเวที (เช่น Hotspot มือถือส่วนตัว)

## 4. แผนสำรองบนเวที (Safety Net)

| เหตุการณ์เฉพาะหน้า | วิธีรับมือทันทีโดยไม่เสียจังหวะ |
|---|---|
| **แชทยังไม่เด้งขึ้นฝั่งตรงข้าม** | แชทใช้ Polling ทุก ~8 วินาที — หากพูดจบประโยคแล้วยังไม่ขึ้น ให้กด Pull-to-refresh หรือรีเฟรชหน้า `/orders/[id]` เบาๆ 1 ครั้ง |

| **เน็ตฮอลล์ช้า / โหลดรูปไม่ทัน** | เปิดไฟล์ภาพนิ่งจาก [ui-snapshots/set-flow](file:///D:/Project/GongDong-Hack-DII/frontend/ui-snapshots/set-flow) และ [ui-snapshots/cod-flow](file:///D:/Project/GongDong-Hack-DII/frontend/ui-snapshots/cod-flow) ที่ใส่ไว้ในสไลด์สำรองท้าย Deck เพื่ออธิบายต่อจนจบ 7 นาที |
